# AI Task Generation Workflow (current)

**This replaces the earlier "hybrid rule-based + AI second opinion"
design.** `WorkloadAI.php` (the rule-based scoring engine) is no longer
called anywhere in the AI recommendation path — it is left in the
codebase, untouched, in case anything else in the system still needs
it, but `ajax_ai_recommend.php` does not `require` or reference it.

## New flow

```
Admin selects Committee + types Task Title
      |
Clicks "Generate with AI"
      |
ajax_ai_recommend.php
      |
Gathers ACTUAL active members of that committee + their REAL,
current metrics (workload, completion rate, on-time rate, overdue
tasks, active committees, days since last assignment) — queried
directly from the database, no WorkloadAI involved
      |
includes/OllamaAI.php -> Ollama Local API (http://localhost:11434)
                                  |
                          qwen2.5-coder:7b (format=json)
                                  |
      +---------- validated JSON ----------+
      |
Description, Recommended Member, Priority, Workload Points,
Due Date, Status, Reasoning
      |
All fields auto-fill into the Assign Task modal — every one
of them stays fully editable. Description shows an
"AI Generated by Ollama" badge until the admin edits it.
      |
Admin reviews/edits and clicks Save Task -> ajax_save.php
(re-validates everything regardless of origin)
```

## What changed, file by file

| File | Change |
|---|---|
| `includes/ai_config.php` | Default model changed to `qwen2.5-coder:7b`; default timeout raised to 45s (task generation does more work than a single ranking call). |
| `includes/OllamaAI.php` | Rewritten. New method `generateTaskRecommendation(taskTitle, committeeName, members)` replaces the old `analyze(task, candidates)`. Prompt now asks for a full task (description/priority/points/due date/status/reasoning), not just a pick among pre-scored candidates. Validation now also checks priority/status enums, a 1–100 point range, and a real, non-past `YYYY-MM-DD` due date — individually-invalid fields are corrected to safe defaults (with a `warning` explaining what was adjusted) rather than discarding the whole response; only an invented member id fails the whole thing. |
| `modules/workload/ajax_ai_recommend.php` | Rewritten. No longer requires or calls `WorkloadAI`. Queries active committee members and their real metrics directly (mirroring the same math WorkloadAI used internally, just without the scoring/ranking step), sends title + real data to Ollama, double-checks the returned member id against the real member list as an independent second guard, logs the attempt, returns the result. Now requires both `committee_id` and `task_title`. |
| `modules/workload/index.php` | Assign Task modal reorganized: Committee + Task Title + **Generate with AI** button at the top, a loading card, an AI Recommendation summary card (member/priority/points/due date/status/reasoning), then all the same editable fields below (Assign To, Priority, Status, Description with an "AI Generated by Ollama" badge, Workload Points, Due Date). |
| `assets/js/workload.js` | Added the Generate-with-AI click handler: cycles through three loading messages, guards against duplicate in-flight requests (button disables itself), populates every field from the AI response, and clears the "AI Generated" badge the moment the admin types into Description themselves. Falls back to a plain error/unavailable message if Ollama can't be reached — nothing blocks manual entry. |
| `modules/workload/ajax_save.php` | Still re-validates every field the same way regardless of whether it came from AI or manual entry (unchanged rules). Replaced the old `WorkloadAI::markOutcome()` call (which compared against a rule-based pick that no longer exists in this workflow) with a small inline function that instead compares the final assignment against the **AI's own** recommended member id, recorded in the new `admin_followed_ai` column. |
| `includes/WorkloadAI.php` | **Untouched.** Still fully present, still usable by anything else in the system (e.g. the "Workload Recommendation" panel on the module's main page, which uses its own simple lowest-active-points query and was never wired to WorkloadAI's scoring engine anyway). |
| `database/migration_ai_task_generation.sql` | New. Adds `ai_generated_fields` (TEXT) to `ai_recommendations`, storing the validated `{description, priority, workload_points, due_date, status}` object. Run this after `migration_ai_hybrid.sql`. |

## Member background context

Committee member recommendations may include optional data from the
`user_background` table: education, profession, experience, expertise,
skills, government/legislative experience, and recent assignment summaries.
The data is limited to task-relevant context; passwords, OTP data, email
addresses, and session credentials are never sent to the AI provider. The
administrator still reviews and confirms the selected member manually.

Install `database/migration_user_background.sql` after `database/schema.sql`
before using the background fields in User Management.

## Not changed

- `modules/workload/ai_settings.php`, `ajax_test_ai_connection.php`,
  `ajax_save_ai_settings.php`, `assets/js/ai-ollama-settings.js` — the
  Local AI connection settings/test panel works exactly as before and
  still controls the model/URL/timeout used by this new workflow.
- The database schema otherwise (only the one new column above).

## Setup / model note

The default model is now **`qwen2.5-coder:7b`** (~4.7GB), which is
larger than the `qwen2.5:1.5b` used previously. Pull it with:

```bash
ollama pull qwen2.5-coder:7b
```

If you'd rather keep using a smaller model, nothing is hardcoded —
just type the model name you already have (e.g. `qwen2.5:1.5b`) into
**Smart AI Settings → Local AI (Ollama) → Model** and save. The task-
generation prompt works with either; a smaller model may occasionally
need more of its fields auto-corrected by the validation layer (you'll
see an "Adjusted" badge with a tooltip explaining what changed).

## Fail-safe behavior (unchanged in spirit)

If Ollama is disabled, unreachable, missing the model, times out, or
returns something that can't be validated, `btnGenerateAI` shows a
plain "AI task generation is currently unavailable — please fill in
the task details manually" message and nothing else is blocked: every
field is still there, empty and editable, exactly as before this
feature existed.
